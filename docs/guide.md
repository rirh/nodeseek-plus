# NodeSeek++ 使用说明

[← 返回 README](../README.md)

## 帖子监控

### 配置

NodeSeek 监控使用 https://rss.nodeseek.com/，每轮读取一次订阅，需要允许脚本连接 `rss.nodeseek.com`。该订阅不覆盖 DeepFlood，因此 DeepFlood 页面不启用监控。监控入口位于右侧工具栏第一位；主面板只展示正则匹配到的帖子，点击「配置」打开独立弹窗：

- **监控正则**：每行一个表达式，任意一条命中 RSS 标题即收录，不读取摘要或正文。
- **刷新间隔**：60–3600 秒，默认 300 秒。
- **更新**：保存配置、清空旧结果与未读，并立即检查一次。

不带分隔符的表达式默认忽略大小写，也支持 `/表达式/标志` 格式。无效正则会提示错误，不会应用。

```text
vmiss|搬瓦工
/香港.*(年付|月付)/i
```

第一行匹配包含 `vmiss` 或「搬瓦工」的标题；第二行匹配「香港」后出现「年付」或「月付」的标题。不同规则按顺序分色。

不会写正则时，可以把需求交给 AI，例如：

> 请生成 JavaScript 正则，匹配包含 vmiss 或搬瓦工、但不包含已出的帖子，忽略大小写。按 /表达式/i 格式输出，每行一个，不要代码块。

检查生成结果后再使用。输入框旁的帮助图标可打开 [MDN 正则表达式文档](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide/Regular_expressions)。

### 刷新与提醒

- **刷新**立即检查一次，跳过轮询等待；正在执行时不会重复并发。
- **停止 / 启动**控制自动监控；停止后仍可手动刷新。底部显示下次检查倒计时及暂停、检查中、冷却中等状态。
- 首次检查只记录 RSS 当前返回的最新帖子 ID，不把已有帖子当作新帖提醒；之后只处理更新的帖子，刷新页面仍保留进度。请求失败或返回旧数据不会推进或回退位置。
- 新匹配的帖子去重提醒，最多保留 200 条未读；打开面板后清空未读标记。面板展示最近 200 条匹配帖子，以及检查轮数、累计帖子数、符合与不符合数量；更新配置后统计重置。
- 系统通知默认开启，优先使用油猴 `GM_notification`，点击可打开帖子；不可用时尝试已授权的浏览器通知。操作系统需允许浏览器或脚本管理器显示通知。

后台标签页也会检查，但论坛页面必须保持打开。浏览器休眠、标签页冻结或系统休眠可能推迟轮询。订阅仅覆盖其当前返回的帖子，不保证捕获轮询间隙的所有帖子。

### 抽奖追踪

登录后可在帖子页的监控面板中选择「追踪当前抽奖帖」。标题出现「已开奖」「开奖结果」等文字时给出提示，需自行打开帖子核实，脚本不会判断是否中奖。

## 图片上传与快捷回复

在设置中选择图床协议，然后在编辑器旁选择图片，上传后自动插入链接。支持多选、粘贴和拖拽，也可点击编辑器原有的图片按钮。

- **NodeImage**（默认）：固定使用官方 API，通过脚本管理器跨域上传，需允许连接 `api.nodeimage.com`。脚本会通过 NodeImage 登录会话自动获取密钥；未登录时点上传栏中的官网入口，完成 NodeSeek 授权后返回重试。
- **Telegraph、Telegraph2、LskyPro、Chevereto、EasyImages**：需填写图床地址，服务须支持所需接口与 CORS；凭据只保存在当前页面内存，刷新后需重新输入。

列表中分类标签后的「快速回复」按钮打开快捷回复面板，可搜索、新增、修改和删除模板。**点击模板内容会直接发送回复**，需要站点登录和相应权限。

## 消息中心

@我、回复主题作为固定联系人，与系统消息和私信会话共用左侧列表，右侧页内查看通知或聊天。

已拉取的私信会话和聊天记录存入当前浏览器的 IndexedDB，按站点与账号隔离。每次同步按消息 ID 去重合并，不会因服务器只返回近期数据而删除本地旧记录，也不自动过期；只能保存已经拉取过的内容。长会话先显示最近 200 条，可继续加载更早的本地记录。

聊天输入区默认使用 Markdown 编辑器，支持常用格式、表格、撤销/重做、预览与导入 `.md` 文件。图片上传复用设置中的图床，图片处理完成前不能发送。可随时切换回「原版编辑器」，两者不会同时出现，也不会自动发送草稿。

## 用户资料与徽章

「等级、信任分与身份徽章」中可单独关闭「用户资料悬浮预览」。默认开启，桌面鼠标停留约 300ms 后显示；手机及窄屏保留站点原有点击行为。徽章默认保留原有彩色样式，也可选择柔和单色或自定义颜色。

## 请求与缓存

「其他 → 接口请求并发与延迟」可设置同页站内请求的最大并发数（1–10，默认 4）和相邻请求启动间隔（0–5000ms，默认 200ms）。首个请求立即执行；翻页、签到等用户操作优先于排队的资料请求。各标签页独立调度，403、429、503 会共享冷却状态，暂停后续请求至少 60 秒，并遵守更长的 `Retry-After`。

用户资料按站点缓存 24 小时（最多保留最近 3000 人，只存徽章和资料卡用到的字段），刷新和翻页优先复用；缓存在页面加载时读取一次，一批请求完成后合并写回一次；同一用户的并行读取共用一次请求，失败结果不缓存。可见作者优先加载，屏外作者接近视口时再加载。列表互动计数默认悬停后读取，需要自动预读时可在「原生列表增强」中开启。

后台页面会暂停无用的界面扫描和动画，监控检查与系统通知继续运行。

## 数据与权限

- 常规配置、监控结果、历史和回复模板保存在脚本管理器的本地存储中，部分数据按站点及账号隔离。
- 导出的设置不含运行历史和密钥字段；监控正则独立保存，不随设置导出。
- 「清空缓存」清除用户资料、通知计数和回帖足迹缓存，保留配置、阅读历史和监控记录。
