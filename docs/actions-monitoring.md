# 操作与监控模块

## 已实现

- `actions.ts`：签到、模板插入、草稿恢复/删除、显式启用的 Ctrl+Enter 提交。签到入口默认开启且仅手动；自动签到另设开关，默认关闭。缓存以站点、账户、上海日期隔离，仅成功或服务明确已签到时写入。
- 草稿在输入停顿 500ms、离开页面及模块清理时保存，以账户和页面路径隔离。恢复只允许空编辑器，不覆盖正在写的文本；30 天前的草稿不恢复。没有收到可信提交成功事件前不自动清除草稿。
- `actions-upload.ts` / `actions-upload-protocol.ts`：NodeImage、Telegraph、Telegraph2、LskyPro、Chevereto、EasyImages 六类协议；选择文件触发上传，结果插入当前编辑器。API Key / Token 只保留当前页内存，刷新后重新输入，不写入设置导出。自定义服务地址要求 HTTPS。
- `monitoring.ts`：最新交易、最新抽奖、标题关键词共用页面抓取结果。每次最多抓首页和交易页各一次，最短 60 秒，页面隐藏时不启动请求。关键词按账户和帖子去重，记录保留最多 1000 条、7 天。
- 抽奖追踪由用户主动添加，最多 50 条、30 天。每轮最多检查两个追踪帖，同帖至少间隔 10 分钟；以标题的开奖/结束文字作为提示线索，不将全文中的用户名误认成中奖证明。
- 定时翻页默认关闭且必须手动开始，页面不可见时暂停倒计时；使用站点现有 `.nsk-pager a.pager-next` 或明确 next 链接，不构造分页 URL。

## 明确限制

- 尚未在真实登录账户执行签到、发帖、上传和中奖核实；DOM 和接口契约来自给定的上游源码，需真实环境验收。
- 原生 Fetch 受 CORS 约束，不能替代 GM 跨域权限；图床必须允许当前论坛 Origin。没有自动获取 NodeImage 登录 Key，没有自动重试上传，避免重复创建远端文件。
- 没有“确定中奖”自动判断：上游全文匹配用户名的方式不可靠。本版提供标题更新提醒和帖子入口，需要用户核实具体中奖名单。
- 签到和监控复用 `lib/tab-lock.ts`：Web Locks 的 `ifAvailable` 防止同站同账户标签页并发，GM 持久时间戳防止依次获取锁后重复请求；监控结果通过 GM 共享。无 Web Locks 时退回一次 GM 租约竞争，不忙等、不自动排队；GM 不提供原子比较交换，极端同时启动仍可能重复，异常关闭最长等待 120 秒租约过期。已在当前页面执行的请求不会仅因切换到后台而中断，后续轮询暂停。
- 定时翻页到新页面后停止，需要再次开始，不会持续无人值守翻页。
- 快捷回复兼容每行一条文本，也支持 JSON 数组 `[{"group":"常用","title":"感谢","body":"感谢分享"}]`；每组选项通过下拉菜单选择后手动插入，正文支持换行。配置导入导出自然保留分组，不提供独立的分组管理弹窗。草稿按 URL 页码区分，尚不提供草稿总览。
- 监控不维护第二套阅读历史，标题链接由公共阅读模块统一处理。

## 验证

`node --experimental-strip-types --test tests/actions-upload.test.ts tests/actions-templates.test.ts`：6 个测试通过，另覆盖旧模板兼容、分组与多行正文、畸形 JSON 拒绝；其中图床测试，覆盖六图床请求/响应契约、EasyImages匿名路径、错误响应及不安全 URL 拒绝；不代表远端服务支持 CORS。
